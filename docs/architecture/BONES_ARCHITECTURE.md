# Кости (Bones) и привязка: архитектура

## 1. Уровни (по возрастанию сложности)
1. **Parenting слой→слой** (сделано): `links: Map<childId, parentId>`; ребёнок повторяет *дельту* трансформации родителя.
2. **Кости**: иерархия костей, слои привязаны к костям (жёсткая привязка, один слой = одна кость).
3. **Mesh/Warp**: вершины сетки с весами нескольких костей (skinning). Отдельный подшаг.

## 2. Parenting (как устроено сейчас)
Для узла N: `delta(N) = delta(parent(N)) * P * L(N) * P⁻¹`, где `L` - локальная трансформация (T·R·S вокруг пивота),
`P` - мир родителя N в дереве PSD. Мир ребёнка: `delta(parent) * P_child * L_child`.
- нулевая трансформация родителя => ребёнок на месте (нет прыжка при привязке);
- цепочки работают, циклы запрещены в VM (`setParent`) и безопасны в `SceneBuilder`;
- жесты считаются через `parentWorlds` (теперь включают привязку), рамка выделения ребёнка следует за родителем.
Ограничение: внутри привязанной ГРУППЫ дельта детей считается без учёта привязки самой группы (точно, пока нет связей внутри групп).

## 3. Кости
**Данные** (`ProjectData.bones: List<Bone>`):
```
Bone(id, name, parentBoneId?, x, y, length, angle)   // x,y - позиция сустава в координатах родителя; angle - радианы
```
Поза кости хранится как `LayerTransform` (dx,dy,rotation) под id кости из диапазона `BONE_ID_BASE = 200_000`, поэтому **ключевые кадры,
easing, undo, сохранение работают без нового кода**: кость - это узел анимации. Bind-поза = поля `Bone.x/y/angle`; анимация = `LayerTransform` поверх.
**Мировая матрица кости**: `W(b) = W(parent) * T(x,y) * R(angle) * [анимация]`. Рендер-поза: `Pose(b) = W_anim(b) * W_bind(b)⁻¹` - это и есть дельта,
которая применяется к привязанному слою (та же формула, что у Parenting; Parenting - частный случай, где «кость» = слой).

**Привязка**: `boneBindings: Map<layerId, boneId>`. Реализуется ровно как `links`, только родитель - кость: `delta(boneId)` в `SceneBuilder`.
Автопривязка: пересечение bbox слоя с отрезком кости (кость с наибольшим перекрытием); вручную: выбрать слой → «Привязать к кости».

**Режимы**:
- *Bind Pose* («Настройка»): правка меняет `Bone.x/y/angle`, `Pose = identity` => картинка не деформируется;
- *Animation*: правка пишется как обычная трансформация кости (`storeEdit`), ключи на таймлайне.

**UI**: инструмент «Кости» (переключатель в верхней панели). «Добавить кость»: протяжка пальцем от сустава к концу создаёт кость
(родитель = кость, у которой начало в радиусе тапа, иначе корень). Тап по кости выделяет её (рамка-капсула в экранных координатах, как рамка выделения),
вращение - ручка на конце кости; поля X/Y/Rotation инспектора работают для кости как для слоя.

**C++**: матрицы костей до рендерера не доходят - Kotlin считает дельты и подмешивает их в аффинную матрицу каждой операции слоя
(формат сцены не меняется). Для Mesh (подшаг 3) добавится массив матриц костей (`mat3 bones[N]`) и атрибуты `boneIndex/weight` вершин в вершинный шейдер.
