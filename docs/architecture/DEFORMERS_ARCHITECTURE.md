# Деформеры: архитектура (Warp, Mesh, Perspective сделаны; Turbulent, Liquify, веса костей - дальше)

## 1. Принцип
Деформация - это **вершинный шейдер + данные на слой**; формат сцены (ops/params) не меняется.
Слой рисуется либо единичным квадратом (6 вершин, как раньше), либо **статической сеткой 24x24** (VBO + IBO создаются один раз
в `initGL`). Данные деформера (смещения точек) передаются в C++ отдельным вызовом `setWarps(ids, offsets)` вместе со сценой
(`SceneData.warpIds/warpData`, `VtRenderer.applyScene`) - то есть раз на изменение, а не раз на вершину.

## 2. Warp (готов)
- 16 контрольных точек (4x4 = сетка 3x3 ячеек), смещения в долях размера слоя; вершина смещается бикубической поверхностью
  Безье: `pos = uv + sum(B_i(u) * B_j(v) * off_ij)`, uniform `uOff[16]`, флаг `uWarp`.
- Точка = обычный узел анимации с id `WarpMath.pointId(layer, k)` (диапазон от 1 000 000). Её смещение - `LayerTransform(dx, dy)`.
  Поэтому ключи, плавность, Undo, сохранение, экспорт работают без нового кода.
- **FX** (кнопка в верхней панели и на таймлайне): выкл = Bind Pose - правка меняет `base` (форма привязки), анимация не показывается;
  вкл - правка пишется ключом на текущем кадре как дельта от формы привязки. Итог: `bind + track(frame)`.
- Текст растеризован в текстуру, поэтому гнётся так же, как картинка.

## 3. Mesh (сделан: модель, Делоне, Cut, Smudge, генерация по контуру; веса костей - дальше)
Реализация: `MeshMath` (триангуляция Bowyer-Watson, `addVertex` делит треугольник, `trianglesHit`/`removeTriangles`/`compact` для Cut, `fromAlpha` по карте прозрачности из C++), id вершин `100_000_000 + layer*1024 + k`, рендер: динамический VBO (позиция + uv) и `glDrawElements`, `Renderer::setMeshes`. Ниже - исходный план (формат вершин в коде: u, v, dx, dy).
- Данные: `Mesh(layerId, verts: [x, y, u, v], tris: [i0, i1, i2])`; позиция вершины - `x, y` в долях слоя (поза привязки), `u, v` фиксированы.
- Вершинный шейдер получает атрибуты `aPos(u,v)`, `aRest(x,y)`, `aOff(dx,dy)`; **VBO dynamic**: при смене кадра обновляется только поток `aOff`
  (`glBufferSubData`), индексы статичны. JNI: один `FloatArray` на слой.
- Каждая вершина - узел анимации (id `MESH_ID_BASE + ...`), как точки Warp; Smudge Mesh меняет смещения группы вершин в радиусе кисти.
- Cut Mesh: удаление треугольников (индексы), Generate Mesh: сетка по плотности.

## 4. Кости и вершины (skinning)
- Вес вершины: до 4 пар `(boneId, weight)` -> атрибуты `aBones(ivec4)`, `aWeights(vec4)`.
- В шейдер уходит массив матриц костей `uBone[N]` (дельты `SceneBuilder.boneDeltas`, переведённые в пространство слоя): `p = sum(w_i * M_i * p_rest)`.
  Сейчас кость двигает слой целиком (жёсткая привязка через `links`); skinning заменит это для слоёв с Mesh.
- Авто-веса: по расстоянию вершины до отрезка кости (обратное квадрату), нормировка суммы до 1.

## 5. Perspective, Turbulent Displace, Liquify
- **Perspective**: 4 угла; проективное преобразование в шейдере (`w` в gl_Position, UV с поправкой на перспективу).
- **Turbulent Displace**: фрагментный шейдер, шум (simplex/value) смещает UV: `uv += noise(uv * size + time) * intensity`; `Line Boil` - `time` из номера кадра, дискретно.
- **Liquify**: деструктивная кисть, правит пиксели текстуры (offscreen FBO), без ключей.

## 6. Ограничения текущей версии Warp
- Hit-test (тап по слою) и рамка выделения работают по недеформированной форме.
- Ключи точек Warp показываются на таймлайне бледными ромбами, но выделять и двигать их рамкой пока нельзя (только ключи самого слоя).
- Кости к точкам Warp не привязываются (только к слою целиком).

## Perspective (сделан)
4 угла слоя - узлы анимации (`PerspectiveMath.pointId`, база 300_000_000). `PerspectiveMath.matrix` строит гомографию квадрат -> четырёхугольник (Heckbert), 9 float по столбцам идут в C++ через `setPerspectives`; вершинный шейдер делит `uH * vec3(pos, 1)` на `w`. Слой с перспективой рисуется сеткой 24x24, чтобы текстурные координаты интерполировались достаточно точно.

## Веса костей (сделан в первой версии)
`SkinMath` считает веса по отрезку кости: `w = strength * length / max(dist, 1px)`, топ-4, нормировка. `SceneBuilder` для слоя из `skins` (слой с Mesh) не применяет link-дельту, а смещает каждую вершину: `p' = sum(w_i * D_i(p))`, где `D_i` - дельта позы кости; результат переводится обратно в единицы слоя и идёт в `meshVerts` как смещение. Это CPU-скининг на кадр (вершин <= 1024); GPU-атрибуты `aBones/aWeights` не нужны. В `project.json`: `skins: {layerId: {boneId: strength}}`.

## Turbulent Displace (сделан)
`Turb(intensity, size, complexity, boil)` хранится по слоям (`ProjectData.turbs`). `TurbMath.params` даёт 4 числа `(intensity, size, complexity, seed)`, где `seed = frame / boil` (Line Boil). Фрагментный шейдер (`kFragTex` и `kFragBlend`) сдвигает UV на `(fbm(p), fbm(p + 31.4)) - 0.5`, `fbm` - value-noise до 6 октав. Передача: `SceneData.turbIds/turbData` -> `RenderNative.setTurbulence` -> uniform `uTurb`.

## Liquify (сделан для картинок)
`LiquifyMath.push` - обратное отображение: пиксель в круге берёт цвет из точки, сдвинутой назад на `delta * falloff(d, r)` (билинейно, с учётом альфы). Рабочий буфер - `IntArray` картинки слоя, после каждого шага `Bitmap.setPixels` + `RenderNative.uploadBitmap`; в конце мазка PNG пишется в файл проекта (в фоне). Откат - до 3 копий буфера в памяти. Для PSD-слоёв нужен отдельный слой правок (пока нет).

## Effect Pipeline (эффекты слоя на FBO)
Слой с эффектами рисуется так (`Renderer::drawLayer`): 1) слой (с Warp/Mesh/Perspective/Turbulent) рисуется в FBO `A` с opacity 1 и режимом Normal; 2) для каждого эффекта цепочки берётся свободный FBO `B`, полноэкранный проход `kFragFx` читает `A` и пишет в `B`, затем `A` возвращается в пул и `A = B` (ping-pong, два FBO на всю цепочку); 3) итог `A` накладывается на родителя с opacity и режимом слоя (`compositeFbo`), FBO возвращается в пул. Все эффекты - режимы одного шейдера (`uMode`, параметры `uP0/uP1`), поэтому цепочка Хромакей -> Размытие -> Цветокоррекция - это три прохода без пересборки программ. Размеры и расстояния в параметрах заданы в пикселях холста и умножаются на масштаб вида, поэтому превью и экспорт дают одинаковый результат. Время для Wave/Noise/Shake берётся из кадра проекта (детерминированно). Spin - не шейдер: угол добавляется к `rotation` слоя в `transformsNow` и при экспорте. Данные: `Effect(type, p[8])`, `ProjectData.fx`, `SceneData.fxIds/fxCounts/fxData`, JNI `setEffects`.
Ограничение: слой в clipping-цепочке рисуется без эффектов (`clipMode`).

## Камера и видео
Слой `MediaKind.CAMERA` не рисуется; `SceneBuilder` строит матрицу вида `T(c) * S(z) * R(-rot) * T(-(c + d))` и умножает на мир всех корней, поэтому Pan/Zoom/поворот работают одинаково в превью и экспорте. Видео: `VideoFrames` берёт кадр источника через `MediaMetadataRetriever` на отдельном потоке (запросы по слою сливаются) и заменяет текстуру слоя; кадр = `offset + local * speed` с учётом reverse/freeze. Декодер MediaCodec не используется: покадровая выборка проще и точна для скраббинга, но медленнее на длинных видео.

## Mesh: патчи и плавная деформация (проект и что сделано)
**Цель:** деформация как в Clip Studio Paint - без заломов Делоне, плавная между точками.
**Целевая структура (патчи Безье/Эрмита):** сетка из прямоугольных ячеек; у узла: `uv` (исходное положение), `pos` (текущее XY) и две касательные `tu`, `tv` (векторы по рёбрам). Ячейка - бикубический патч Эрмита: `P(s,t) = sum Hi(s) Hj(t) * C_ij`, где C - четыре угла, их касательные по `s` и `t` и перекрёстные производные (скручивание, по умолчанию 0). Касательные по умолчанию - разность соседей (Catmull-Rom), поэтому сдвиг одной точки плавно тянет 4 соседние ячейки без заломов (C1). В C++ патч рисуется сеткой NxN вершинным шейдером: в атрибутах `(s,t)` и массив 16 контрольных значений на ячейку (uniform buffer), позиция = базис Эрмита; UV считается по исходному патчу (билинейно). Недостаток: нужна регулярная топология; при Cut/удалении точек из прямоугольной сетки патч теряет соседей.
**Реализовано (произвольная топология):** треугольная сетка остаётся, а в `SceneBuilder` перед отправкой в шейдер вызывается `MeshMath.smooth`: каждое ребро делится пополам (1-2 уровня), смещение середины ребра = `3/8 (a+b) + 1/8 (c+d)` (правило ребра Loop, c и d - вершины напротив; на границе - среднее). Исходные вершины сохраняют смещение (интерполяция), поэтому ручные точки не уплывают, а поверхность между ними гладкая. Работает с Cut/Add/Delete Point, не требует регулярной сетки. Следующий шаг при необходимости - настоящие патчи Эрмита для регулярных сеток.
**Удаление точки:** `MeshMath.removeVertex` находит кольцо соседей и закрывает дыру методом «отрезания ушей» в пикселях слоя; граничные вершины просто теряют треугольники; затем `compact` и перенос ключей на новые индексы (`remapMeshIds`).
**Кривые:** `Keyframe.curve = [x1,y1,x2,y2]` (cubic-bezier, y можно за пределами 0..1) важнее `easing`; `Keyframe.ease(t)` решает `x(s)=t` (Ньютон + бисекция). Редактор универсален: правит все ключи на текущем кадре у выделенных узлов и точек деформеров слоя.

## Puppet Mesh (пины)
Пин `Pin(u, v, stiff, radius)` - точка слоя в исходном положении; его смещение лежит под id `PuppetMath.pinId = 500_000_000 + layer * 64 + k` (как вершины, значит работают FX/ключи/Undo/кривые/таймлайн). Смещение вершины = взвешенное среднее смещений пинов: `d(v) = sum(w_i * delta_i) / max(1, sum(w_i))`. Вес мягкого пина (Move) - гауссов спад `exp(-d^2 / 2s^2)`, `s = R / 2.4`, приведённый к нулю на радиусе (нет скачка на границе); жёсткого (Stiff) - «полка» 1 до `0.6 R` и smoothstep до 0 на `R`. Деление на `max(1, sum w)` не даёт суммарному смещению превышать смещение пинов, когда радиусы перекрываются. Считается на CPU при сборке сцены (`MeshMath.offsets + PuppetMath.addTo`), затем `MeshMath.smooth` сглаживает сетку при отправке на GPU. Без сетки пин создаёт её по контуру слоя.

## Многоузловая кривая плавности
`Curve(nodes)`, узел `CurveNode(x, y, inX, inY, outX, outY)`: время и значение узла и два вектора усиков относительно узла. Между соседними узлами a и b - кубическая кривая Безье с контрольными точками `a + out_a` и `b + in_b`; по времени усики ограничены сегментом, поэтому `x(s)` монотонна и значение однозначно (решается бисекцией по `x(s)=t`). Кривая проходит через все узлы (C0), гладкость на узле C1 обеспечивается, когда In и Out коллинеарны (при добавлении узла усики берутся по касательной). Хранение: `Keyframe.curve = [n, x,y,inX,inY,outX,outY, ...]`; старый формат из 4 чисел читается как два узла (обратная совместимость). Пресеты Bounce/Elastic/Back/Wave строятся по функции выборкой в узлы с усиками по Catmull-Rom (`Curve.fromFunction`).

## ARAP для пинов (Kotlin, без Eigen)
`ArapSystem` (domain/anim/ArapMath.kt): котангенс-Лапласиан сетки в CSR (веса отрицательных углов ограничены снизу 1e-3), цикл «локально-глобально» (6 итераций): локально - поворот каждой вершины `theta = atan2(S10 - S01, S00 + S11)` по ковариации рёбер; глобально - решение `L p = b` для свободных вершин методом сопряжённых градиентов (закреплённые вершины переносятся в правую часть). Структура (соседи, веса) строится один раз на сетку и кэшируется (`WeakHashMap` по сетке + размер слоя + хэш смещений), на кадр выполняются только итерации. Eigen/SimplicialLDLT не подключён: он нужен для сеток в десятки тысяч вершин, при лимите 1024 вершин CG быстрее по накладным расходам и не требует внешней зависимости в NDK. Ограничения пинов: `PuppetMath.addTo` фиксирует кластер вершин вокруг пина (цель = исходная позиция + смещение пина), якоря вне радиусов остаются на месте; итог умножается на нормированное влияние (`FULL_INFLUENCE = 0.35`) - плавный спад на краю радиуса.
**Генерация:** маска alpha > 15 -> closing -> dilation 4-6 px -> граничные точки + равномерные внутренние точки -> Делоне (Bowyer-Watson) -> отбор по «центр или >= 2 середины рёбер». Constrained Delaunay (жёсткие рёбра контура) не реализован: отбор по маске даёт тот же результат на практике, но на очень вогнутых фигурах возможны лишние «перемычки» между близкими прядями.

## Deform Path, мягкие пины, геодезия, кисть (Kotlin)
- `PathMath`: центрипетальный Catmull-Rom через пины. Вершина хранит локальную систему линии: длину дуги `s` в ПИКСЕЛЯХ, смещения вдоль касательной `u` и нормали `d`. Проекция - на отрезок между сэмплами; за концами линия продолжается по касательной. Новая позиция: `C(s) + T(s)*u + N(s)*d`, смешение по smoothstep-весу. Длина дуги абсолютная, поэтому прядь не растягивается. Включается с `PuppetMath.PATH_MIN_PINS` = 3 пинов.
- `MeshGraph.geodesic`: Дейкстра по рёбрам. Вес пина и линии считается по геодезическому расстоянию, поэтому влияние не перепрыгивает на несвязные пряди (расстояние = бесконечность).
- Мягкие пины: ARAP решает `(L + Lambda) P = b + Lambda P_target`, где `Lambda = 100 * min(1, sum w)`; цель - нормированное среднее смещение пинов с доминированием `sharp(w) = w / (1.02 - w)` (пин в своём центре идёт точно за пальцем). CG с диагональным предобуславливателем. Stiff-пин дополнительно закрепляет кластер.
- `BrushMath`: кисть по вершинам, ядро Вендланда C2, шаги по 25% радиуса, после шага сглаживается поле СМЕЩЕНИЙ (не позиции): граница не стягивается. Режимы Grab/Smooth/Bloat/Pinch.
- Тесты: `DeformTest` (дуга и длина пряди, тождество без смещений, изоляция, мягкие пины, кисть).
- Авто-сетка (`MeshMath.fromContourAuto`): шаг `clamp(sqrt(W*H) / (18*sqrt(C)), 16, 128)`, где `C = P^2/(4 pi A)`; периметр - среднее числа граничных рёбер и граничных пикселей (без завышения на диагоналях). Затем упрощённый Рупперт (центры описанных окружностей треугольников с углом < 22 градусов, 3 прохода, не больше 1024 вершин) и лапласово сглаживание внутренних вершин без переворота треугольников.
- Кисть: мазок мутирует локальный буфер, сцена обновляется не чаще ~60 Гц, ключи пишутся одной пачкой на отпускании пальца (`commitBrush`).
- Хит-тест (`Renderer::hitTest`): для слоя с сеткой точка ищется на деформированной сетке (позиции u+dx, v+dy), текстурные координаты берутся барицентрически из найденного треугольника, альфа проверяется с допуском +-2 текселя.
- `PuppetMath.PATH_MIN_PINS` = 2: с двух пинов работает Deform Path.
- `TrackGroups`: все дорожки слоя (трансформация, Warp, вершины Mesh, Perspective, Turbulent, пины). Ключ «слой + кадр» на таймлайне = все ключи этих дорожек; копирование/вставка пачкой, перенос на другой слой через `remap` слота.
- Пресеты авто-сетки: Standard шаг x1.5, High шаг x0.55 (до 1024 вершин).
- Правая панель: полоса 36 dp у правого края с `systemGestureExclusion()` (до 200 dp высоты) и `zIndex` поверх холста; без исключения свайп от края срабатывал как системное «Назад».
